# Agent Note: Settings window chrome

Status: implemented

## Problem

设置页同时通过 SwiftUI（声明式界面框架）工具栏背景和 AppKit（macOS 界面框架）窗口透明标志控制滚动材质，作用域重叠。真实 SwiftUI Window（窗口场景）在关闭全窗口标题栏透明度时，把左右两栏顶部都绘成白条。原验证入口手工创建统一工具栏窗口，并强制材质活动状态，没有覆盖生产 Scene（场景）的默认工具栏与窗口背景组合。

问题在窗口装配与绘制职责，而非 SwiftUI 或 AppKit 过时；替换整个设置表单不能解决验证组合不一致的问题。

## Decision

- SettingsWindow 拥有原生统一工具栏样式、标题区几何和窗口级外观。SettingsWindowChrome 保持窗口背景透明及原生全窗口分隔线关闭，通过公开的 contentLayoutRect（内容布局区域）观察真实标题区高度；脱离窗口时取消观察并恢复原始标志。窗口引用为弱引用，排队回调核对当前窗口，几何更新调度到主运行循环。
- SettingsView 拥有分栏、分页与卡片对齐的布局偏好。SettingsTitlebar 作为右侧内容列的固定覆盖层，直接使用卡片实际左边缘定位标题；删去固定宽度工具栏项目及其边距补偿。
- 滚动材质由右侧覆盖层独立拥有，使用 NSVisualEffectView 的 `.titlebar`、`.withinWindow` 与 `.followsWindowActiveState`，正常强调状态为 false。其下方是原生 Divider（分隔线）；顶部时则使用页面底色。窗口级标志不随滚动变化，侧栏不参与右侧材质合成。

该组合替代 [滚动标题栏](../feature/2026-11-05-settings-scroll-titlebar.md)中窗口级标志切换与 `.bar` 工具栏背景的部分，保留其滚动判定；[标题对齐](../bug-fix/2026-11-05-settings-title-alignment.md)继续拥有实际卡片边缘对齐的理由。材质仍由系统公开 API（应用程序接口）绘制，不引入模糊库或私有接口。颜色来源仍由[设置背景配色](../feature/2026-11-05-settings-surface-colors.md)拥有。

## Alternatives considered

- 仅指定统一工具栏，或将工具栏材质修饰符移进详情：真实 Scene 验证仍能复现白条，因为关闭标题栏透明度依然影响整个窗口。
- 把窗口背景改为灰色：只能把白条换成灰条，不能建立正确的窗口内取样与列作用域。
- 全面换用另一套 UI（用户界面）框架：现有原生控件和绑定可继续复用，故障局限在窗口装配层，整体重写增加回归范围。

## Consequences

新增本地 `--validate-settings-scene` 入口在正常 SwiftUI 场景启动后验证真实 SettingsWindow，跳过迁移、权限请求和菜单栏控制器的正式启动。验证任务由应用委托持有，等待窗口有五秒上限，终止时取消任务，完成后恢复应用外观、窗口几何和当前分页。该入口使用默认模型检查视觉装配，不代替业务设置的加载与持久化验证。

真实场景截图覆盖六个分页、浅深外观、上滑和回顶、1100/1500 pt（逻辑点）宽度以及缩回最小宽度。侧栏标题区取样验证滚动前后颜色不变；负向控制分别重新启用全窗口不透明背景或紧凑工具栏，必须失败。窗口观察器另有真实 AppKit 挂载、卸载、样式恢复及解绑后报告值保持的检查。

`--validate-appearance` 保留组件、资源和 Ice Bar 验证，撤去手工窗口对设置标题栏的验收声明；原标题栏负向参数返回替代入口提示。真实窗口不强制覆盖材质活动状态，元数据记录实际前台和焦点状态。当前证据限于 macOS 15.5 / Apple Silicon；公开原生材质会随系统和辅助功能偏好变化，不承诺跨版本像素级复制 Apple 的私有实现。
