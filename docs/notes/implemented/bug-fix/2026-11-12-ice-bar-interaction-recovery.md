# Agent Note: Ice Bar interaction recovery

Status: implemented

## Problem

菜单栏操作等待全部修饰键标志清空，把 Caps Lock（大写锁定）也视为未释放的按键。无超时的等待使点击积压；解除等待后，多个任务同时操作全局鼠标与事件监听器。动态定位在截图加载和面板尺寸变化后重新读取鼠标，并可能使用已隐藏图标保留的原点窗口。加载期间关闭面板后，迟到的结果还能重新显示窗口，但分区状态已被清空，后续隐藏检查会跳过它。屏幕矩形的 `contains` 不包含上边界；实际贴顶点击的纵坐标可恰好等于 `maxY`，因此正确的中间横坐标仍可能被丢弃并回退到最右侧。

## Decision

菜单栏点击入口在调度任何任务或延迟之前，使用原始事件坐标捕获目标屏幕和水平定位点，沿分区切换传给面板；其他入口也在启动打开任务前捕获定位。鼠标命中检测以鼠标所在屏幕为准，不再依赖普通应用的主屏幕。每次打开由面板持有独立请求标识和已捕获的定位。关闭或后一次打开使旧请求失效；加载完成只允许当前且未取消的请求显示。尺寸变化只在原屏幕内调整边界。图标必须实际添加到菜单栏、在屏幕上且属于目标显示器才可作为锚点，否则采用目标屏幕内的触发鼠标位置或右边缘。

菜单栏屏幕归属由同一几何规则拥有，点击入口命中检测和面板定位共同使用。精确上沿优先归属于菜单栏所在屏幕；水平交界先按左闭右开区间判定，最后才接纳外部右边缘。垂直相接时优先下方屏幕的上沿菜单栏。解析屏幕后直接使用已确认的横坐标，不再用普通矩形包含判断二次过滤，也不扩大矩形范围接纳真正位于屏幕外的点。

菜单栏项目管理器统一持有移动、模拟点击和临时恢复操作的互斥状态；调用内部步骤时不重复获取所有权。等待所有权最长两秒，不承诺先进先出，也不无限保留过时点击。临时显示从选择目标到记录恢复位置保持同一次所有权，恢复操作同样受保护；失败通过 defer 释放。只等待 Command、Control、Option、Shift，最长两秒；等待鼠标停止最长一秒。轮询使用可取消的休眠，避免不可取消的事件 continuation（续体）与漏掉按键释放事件。已有任务等待器转发取消并等待子任务退出。

## Alternatives considered

- 仅忽略 Caps Lock：无法解决其他设备标志、取消、积压并发和窗口重新出现。
- 关闭时只隐藏窗口：无法阻止异步加载完成后再次显示。
- 每次尺寸变化重新读取鼠标或隐藏图标位置：定位仍会受移动时机影响。
- 仅在面板打开方法内捕获鼠标：上游点击处理已有 50 毫秒延迟和任务调度，捕获仍可能太晚；若再使用另一块主屏幕，就会误触发靠右回退。
- 只覆盖上沿下方一点，或扩大矩形一圈：前者遗漏真实贴顶事件，后者会误接纳屏幕外坐标并制造多屏重叠。测试同时覆盖精确上沿、屏幕外和交界归属。
- 为每个调用方独立加忙碌标志：设置中的拖动、搜索、悬浮栏和自动恢复仍会争用同一个全局鼠标。

## Consequences

长时间按住修饰键或操作繁忙时，请求会超时并记录日志，用户需松开按键后重试；恢复任务失败继续沿用原有定时重试。此改动不添加配置或依赖，不改变权限与临时图标恢复策略。定位日志记录捕获的显示器、鼠标坐标、水平锚点及显示后的窗口位置，便于区分触发位置错误和后续窗口偏移。

本地应用的 `--validate-ice-bar` 入口验证真实面板的关闭、替换、取消与连接屏幕上三种位置模式的中间/边缘及精确贴顶点击、延迟处理与尺寸变化，保存面板快照与位置元数据，同时覆盖修饰键等待及操作互斥的失败恢复。受控加载和修饰键输入不代表第三方应用已经收到真实点击；辅助功能授权、第三方菜单弹出、显示器拔插及连续人工点击仍需实机验收。
