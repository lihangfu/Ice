# Agent Note: Retire menu bar background blur

Status: implemented

## Problem

用户手测纯高斯壁纸与 MaterialView 方案后仍认为效果很差，明确要求取消顶部菜单栏背景模糊，不再提供此功能。自动化属性和像素检查通过只能证明机制运行，不能替代用户对原生质感的验收。

## Decision

完整删除背景模糊设置、中英文文案、持久化字段、私有前景合成、额外背景截图、专用订阅与异步渲染。移除 MaterialView 的两个构建入口依赖、源码、分发许可证及独立对比程序，同时删除对应验证命令。没有隐藏开关或后备渲染路径。

保留配置 V2 和已有持久化键。解码按 Codable 的未知键语义忽略旧 `wallpaperBlurRadius`，包括该废弃字段的错误类型；后续正常保存不再写出该字段。旧模糊值不再触发覆盖窗口，其他着色、阴影、边框、形状和内缩设置照常读取。无需重置用户偏好，也不修改系统壁纸或系统外观。

保留圆角和分段形状用于遮盖形状外菜单栏的原始壁纸截图。保留 [Ice Bar 原生材质](2026-11-04-ice-bar-backdrop-blur.md)与[跟随系统外观](../bug-fix/2026-11-04-ice-bar-system-appearance.md)；顶部系统菜单栏和弹出 Ice Bar 是不同界面。

本记录合并并取代原壁纸模糊、MaterialView 接入和连续材质原型三份记录；以下保留会影响将来重新考虑此功能的理由与限制。

## Alternatives considered

- 只隐藏滑块或把默认值设为零：旧保存值仍可能启用不可编辑的效果，不满足完整移除。
- 公开 NSVisualEffectView：能提供原生材质，但没有连续半径接口；此前不能满足连续调节要求。
- 将材质放在系统菜单窗口下：原型实测会被系统背景遮挡。放在上方则连系统文字一起模糊，因为原生背景与左侧文字同属一个窗口。测试窗口必须绕过 AppKit 对菜单区域的避让，否则会误判层级实验。
- 普通颜色蒙版、直接盖模糊壁纸或截图重画文字：分别改变前景颜色、遮住文字或产生过期文字；不能满足背景独立与前景实时的目标。修改系统壁纸或透明度偏好会产生全局副作用，未采用。
- 原有私有合成：以无文字上下边缘插值估计背景 B，Apple 菜单区域判断文字极性，CABackdropLayer 读取实时原图 C。黑字使用 dodge/multiply 得到 N × C / B；白字使用 burn/screen 得到 1 − (1 − N) × (1 − C) / (1 − B)，而整体反相曾产生偏色。statusBar 的 sublevel −1 让右侧原始图标保留。背景估计并非系统提供的精确分离，在强纵向变化、高亮菜单和辅助功能设置下可能有残差。
- MaterialView 接入：曾固定 OskarGroth/MaterialView 的 MIT 提交 `b3a04ce56eca69d388c48e9621ce61778fe976c7`，因 Git 网络不可用用同一份原样本地包服务 Xcode、SwiftPM 和对比工具。壁纸与窗口内材质组成不透明视图组，再整体合成到归一化前景；避免重挂 AppKit 图层及独立窗口逐帧截图。它仍依赖私有 CAFilter/CABackdropLayer，panel 预设不是系统菜单材质的精确复刻；能力存在性检查也不保证系统合成语义兼容。

## Consequences

顶部菜单栏现在由系统提供原有背景，Ice 仅应用仍保留的外观设置。此变更不删除系统自身的模糊，也不改变弹出 Ice Bar 的材质。

历史实现保留过 0–30 pt 连续值、带 90 pt 邻域的壁纸、每五秒及空间/外观变化的采样；动态壁纸不是逐帧同步。MaterialView 需把半径写进活动与非活动配置，显式亮度 0 避免默认滤镜冲白，并使用采样 scale 1。深浅材质取系统外观，与恢复文字的黑白极性分开。零、捕获失败、降低透明度与能力缺失时曾隐藏合成；取消和代次检查负责阻止隐藏、拖拽、关闭后的迟到结果。相关运行路径现已全部移除，不再承担这些生命周期与兼容成本。

历史验证仅覆盖 macOS 15.5 / Apple Silicon 的小数半径、实际像素变化、浅深恢复、纹理抑制、黑白文字、背景颜色、形状、拖拽及取消，并以亮度 1 的负向控制捕捉冲白。缺少辅助功能授权时直接调用生产捕获/绘制，未覆盖菜单发现、真实分段几何、完整交互、多屏、其他系统版本或长期性能；这些检查未能证明视觉体验可接受。

退役验证改为旧字段兼容与丢弃、其他外观设置往返保持、真实浅深设置窗口与 Ice Bar、应用构建及依赖移除。未来如重新考虑背景调节，需要新的用户授权与视觉验收标准，不能仅因旧技术检查通过就恢复功能。
