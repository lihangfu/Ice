# Agent Note: Settings scroll titlebar

Status: implemented

## Problem

设置标题栏永久透明且关闭边界，能让静止页面背景融合，却不能在内容上滑时模糊下方内容。用户需要系统设置式的滚动行为：顶部无分界，内容经过标题栏后显示原生材质及轻微边界，回顶后一起消退。

## Decision

设置样式的 IceForm（共享表单）通过布局偏好报告带内边距内容的实际垂直位置；向上越过 0.5 pt（逻辑点）的浮点容差后视为已滚动。滚动裁剪关闭，使真实内容可以经过标题栏下方，供系统窗口内合成取样。该判定与内容关系继续由本记录拥有；材质的窗口装配由[设置窗口装配](../architecture/2026-11-05-settings-window-chrome.md)取代。

原方案采用 SwiftUI（声明式界面框架）的 `.bar` 工具栏背景，并由 `SettingsTitlebarStyle` 在滚动时关闭全窗口透明标志、恢复 `.automatic` 系统边界。此组合在真实 SwiftUI Scene（场景）中将侧栏顶部也绘成白条，已经撤销；不能只凭手工 AppKit（macOS 界面框架）窗口中的材质效果恢复此方案。

分页切换由新表单的布局状态重新决定显隐，避免上一页的滚动状态残留。标题位置继续遵循[标题对齐](../bug-fix/2026-11-05-settings-title-alignment.md)，背景值继续由[设置背景配色](2026-11-05-settings-surface-colors.md)拥有；本决定取代后者永久隐藏标题栏材质与边界的部分。

本功能只作用于设置窗口的工具栏，不增加系统菜单栏背景模糊功能或相关设置。

## Alternatives considered

- 只恢复工具栏自动外观：在当前自定义分栏与表单组合中，顶部也保留独立背景和分隔线，不能满足静止时融合的要求。
- 永久隐藏工具栏背景：内容经过标题区域后仍清晰显示，缺少原生材质与层次提示。
- 保留不透明背景但不允许内容经过下方：仅得到灰色横条，无法体现对真实下层内容的模糊。

## Consequences

原组件预览在 SwiftUI 正常启动前退出，并在手工窗口中强制材质活动状态，不能作为生产窗口的验收证据。该标题栏验证已撤去，真实场景入口、作用域负向控制和窗口观察器生命周期检查由设置窗口装配记录拥有。

原方案的技术取样不能证明视觉体验可接受。后续实现仍应遵循系统外观与辅助功能偏好，并通过真实窗口判断效果。
