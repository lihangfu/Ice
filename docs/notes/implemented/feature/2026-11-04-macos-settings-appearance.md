# Agent Note: macOS settings appearance

Status: implemented

## Problem

设置侧边栏的大标题、单色轮廓图标与内容分组缺少统一层级。需要按 macOS 系统设置的参考图整理界面，同时保留现有设置行为，并避免将窗口视觉样式传播到菜单栏弹出面板。

## Decision

继续使用 SwiftUI（Apple 声明式界面框架）的原生分栏、列表选择、开关和菜单控件。设置窗口通过 `iceFormStyle` 环境值启用专属样式；共享组件的默认样式仍用于其他界面。侧边栏和页面介绍共用图标，内容使用限宽分组、细边框和浅灰底色。页面背景跟随系统窗口颜色，卡片在同一颜色上增加轻微明暗差异，避免纯白卡片造成强烈反差。

设置表单始终保留同一个滚动容器，避免条件设置展开后因溢出而切换视图结构。关于页也采用可滚动分组，让较小窗口能访问全部操作。菜单栏间距的操作与滑块上下排列，减少横向拥挤。

普通设置说明通过 `settingHelp` 交给共用行组件，显示在功能名称之后的圆形问号中。悬停采用系统 Tooltip（悬浮提示），点击可打开相同内容的浮层，供键盘用户访问；辅助功能提示也使用同一份文案。位置、重新隐藏策略等说明由当前选项决定。移除常驻第二行后继续使用现有单行最小高度和分组间距，不靠缩小字号压缩布局。重启应用、注销和更新不可用等风险或状态信息继续直接展示。

带帮助的开关由 `IceToggle` 在原生开关外组织标题与帮助入口，避免 `ToggleStyle` 或 `LabeledContent` 将标签内按钮合并进开关的辅助功能元素。没有帮助的行沿用原布局。帮助浮层显式继承应用语言，避免独立浮层回退到系统语言。

菜单栏布局页的分区用于整理项目，背景复用设置分组的系统灰色，不采样菜单栏或壁纸，也不叠加菜单栏外观着色。加载失败提示使用系统语义文字色，随设置窗口外观适配。菜单栏弹出面板仍保留动态背景；其预览样式不应传播到设置分区。

## Alternatives considered

- 直接修改所有共享组件的默认外观：会同时改变权限窗口和菜单栏外观弹出面板，超出本次设置窗口的范围。
- 使用白色卡片：与用户提供的系统设置灰色背景和低反差分组不符。
- 完全改用系统分组表单：现有自定义颜色、渐变、快捷键和滑块编辑器已有共同布局，整体替换会扩大行为回归范围。
- 让布局分区继续模拟菜单栏底色：分区主要承担排列操作，动态底色会破坏设置页的一致性；图标仍使用真实截图，不将第三方彩色图标统一染色。
- 将问号放在开关之后，或把所有注释自动转换成悬浮说明：前者割裂标题与说明，后者会隐藏操作风险与状态。仅显式标记普通功能解释，由共用行组件在标题后渲染帮助入口。

## Consequences

文字、背景、选择和控件继续使用系统语义颜色与原生交互。浅色和深色外观共享结构；增强对比度时提高卡片边框可见度。新增页面文案同时提供英文和简体中文。

完整应用现在可以通过[Command Line Tools 构建入口](../process/2026-11-04-command-line-tools-build.md)验证。独立预览只覆盖布局与主题，完整应用打包和实际设置窗口的启动检查覆盖真实源码组合；菜单栏行为仍受系统授权状态约束。
