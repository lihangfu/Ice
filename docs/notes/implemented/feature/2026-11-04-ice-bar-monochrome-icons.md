# Agent Note: Ice Bar monochrome icon appearance

Status: implemented

## Problem

Ice Bar 背景已跟随系统外观，但图标来自原始菜单栏截图；浅色外观可能与白色截图图标接近。用户要求先适配单色图标，并保留彩色应用标识和状态颜色。

## Decision

Ice Bar 将可确认的灰度单色截图转为模板，使用系统 primary（主要前景色）随外观更新。[设置布局适配](2026-11-04-layout-bar-monochrome-icons.md)随后扩展了同一遮罩的消费者；原始截图继续保留给搜索结果。此决定部分取代[系统外观记录](../bug-fix/2026-11-04-ice-bar-system-appearance.md)中所有图标原色显示的限制；背景始终由系统外观决定，不恢复按壁纸亮度选择主题。

截图没有原应用的 template（模板）元数据，因此采用保守像素识别。转换到 sRGB 预乘 RGBA 后要求透明周边、存在足够的不透明前景、可见像素接近灰度，且不透明部分的灰度跨度较小。彩色标记、不透明底色、明显双色、空白、低覆盖率及超出大小限制的截图保留原样。具体阈值由 `MenuBarIconAppearance` 拥有，不作为持久化设置。

遮罩结合原透明度、前景明暗极性及灰度覆盖率，保留抗锯齿和镂空，并抑制白色图标原有黑色阴影；按主体灰度归一化，避免灰色图标模板变淡。主题着色使用 SwiftUI 的模板渲染，不改写系统菜单项、点击区域或辅助功能标签。

模板随现有截图刷新批次生成并缓存；同一批次在主线程先更新模板与屏幕信息，再发布原始截图。图标出现彩色状态标记后会删除上一帧的模板，防止沿用旧单色判断。主题切换无需重新分析像素或捕获屏幕。

## Alternatives considered

- 对所有截图直接使用模板渲染：会丢失彩色标记，并把不透明背景渲染成矩形。
- 恢复按图标或壁纸亮度改变背景主题：违背用户已确认的系统外观规则。
- 只增加阴影或描边：不能可靠解决浅底白图标，且会偏离原生控件观感。
- 对含彩色标记的截图分区重新着色：无法从截图可靠区分有意设计的灰度细节和可着色前景，首版保留整个项目原色。

## Consequences

识别是启发式的，无法保证覆盖所有第三方菜单项。低透明度、贴边或双色图标可能保留原色；含彩色标记的整项也可能仍有浅色文字。这里优先避免破坏状态信息，不承诺所有截图都获得同样的对比度。

验证使用实际 IceBarIcon 渲染组件与原生 popover 背景，检查白、黑、灰图标的浅→深→浅像素变化、透明边缘与镂空、彩色标记保色，以及不透明和双色图标回退。`--original-ice-bar-icons-control` 让验证组件显示原图，必须在浅色白图标检查失败。真实菜单项截图另保存浅深对比图；它覆盖实际捕获格式，不替代所有应用状态、点击、多屏和其他 macOS 版本验证。当前实测 macOS 15.5，14 个实际项目中 13 个符合单色条件。
