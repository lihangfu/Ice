# Agent Note: Settings layout icon appearance

Status: implemented

## Problem

设置中的可见、隐藏和始终隐藏分区仍直接显示菜单栏截图，浅色背景上的白色图标对比度不足。用户要求将 Ice Bar 已采用的单色主题适配同样应用于设置布局预览。

## Decision

把[单色识别与遮罩](2026-11-04-ice-bar-monochrome-icons.md)提升到 MenuBarIconAppearance，由现有截图缓存为 Ice Bar 和布局编辑器提供同一批模板。原始截图继续保留，搜索结果仍使用原图；不新增另一套阈值或主题判断。

LayoutBarItemView 保留 AppKit 绘制和拖拽边界。单色遮罩用有效系统外观中的 labelColor（标签颜色）着色，主题变化时重绘；彩色或不明确截图原样显示。绘制和拖拽图像使用同一解析入口，尺寸按原图像素与屏幕倍率计算。不可移动项目的 0.67 淡化在系统标签色之上继续生效；拖拽占位仍保持尺寸并停止绘图，警告图标和鼠标命中逻辑保持原实现。

缓存发布前刷新共享模板；同一项目从单色变为带彩色状态标记时，布局视图替换旧遮罩。订阅弱引用应用状态，避免新增的缓存读取路径延长其生命周期。

## Alternatives considered

- 只修改设置背景：无法让图标跟随主题，也会破坏与系统设置的视觉一致性。
- 在布局视图中另做一次单色识别：重复阈值与计算，可能与 Ice Bar 得出不同结果。
- 只设置 NSImage.isTemplate：直接 NSImage.draw 不具有 SwiftUI 模板控件的自动前景着色语义，采用显式标签色合成。
- 叠加 SwiftUI 宿主替代原布局项目：增加拖拽和鼠标命中边界，当前原生绘制可以满足需求。

## Consequences

单色识别的保守回退沿用原决定：彩色混合项目整项保留，少数截图可能仍然偏浅。实际系统菜单栏和搜索结果未被重新着色。

验证在真实 LayoutBarItemView 上覆盖浅→深→浅、白黑灰图标、镂空、彩色标记与动态替换、供拖拽使用的图像、鼠标命中、禁用淡化和占位尺寸，并保存真实菜单项的浅深布局截图。禁用淡化相对于原标签色的透明度判断，避免把系统标签色自身的半透明误认成错误。负向控制 `--original-layout-icons-control` 恢复原图，必须在浅色白图标检查失败。它不实际移动用户菜单项，跨分区的完整拖拽交互仍需手测。
