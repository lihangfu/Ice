# Agent Note: Menu bar wallpaper blur

Status: implemented

## Problem

用户需要连续调整屏幕顶部系统菜单栏文字和图标背后的磨玻璃效果，拒绝覆盖文字的半透明颜色蒙版。系统菜单背景与左侧文字同属一个 WindowServer 窗口，直接模糊该窗口会模糊文字。公开接口不提供原生背景半径调节。

## Decision

在[统一外观配置](2026-11-04-unified-menu-bar-appearance.md)中保存连续半径，使用 Core Image 对带邻域的壁纸截图先模糊再裁剪。零值保留系统原始背景。持久化和运行时赋值都将半径归一化到 0–30 points；旧配置缺键为零。

复用现有 MenuBarOverlayPanel 的屏幕、空间、形状和壁纸更新生命周期。形状外仍画原始壁纸，形状内才显示模糊合成。壁纸背景按现有五秒计时及外观/空间事件更新，文字由实时 backdrop（背景采样层）读取。

私有接口封装在 MenuBarWallpaperBlurView 中。CABackdropLayer 采样系统菜单窗口，CAFilter 将背景估计 B 从原生图像 C 中归一化，再合成新背景 N：黑字使用 color dodge 和 multiply 得到 N × C / B；白字使用 color burn 和 screen 得到 1 − (1 − N) × (1 − C) / (1 − B)。B 取无文字的上下边缘逐列插值，文字极性取 Apple 菜单区域。该估计不等于系统提供的精确背景分离。

窗口维持 statusBar 层并设置 sublevel −1，处在系统左侧菜单窗口之上、原始右侧状态图标之下，避免改变彩色图标。窗口忽略鼠标事件，交互仍交给系统。几何 mask（裁剪遮罩）仅决定菜单形状，不向文字叠加颜色。

动态检查私有类、实例变量、选择器、滤镜和符号；不支持、捕获失败或降低透明度时隐藏合成。异步计算使用取消与 generation（代次）检查，隐藏、拖拽、关闭、置零均使旧结果失效并恢复窗口 sublevel。配置、空间和显示器由既有管理器拥有；不创建另一组独立窗口，也不改用户壁纸或系统外观偏好。

## Alternatives considered

- 普通半透明颜色蒙版：改变文字和图标，且不是壁纸模糊，不符合需求。
- 在原生菜单窗口下增加 NSVisualEffectView：被系统菜单背景挡住，不能替换现有背景。
- 直接盖上模糊壁纸：遮住同属菜单窗口的左侧文字。
- 截图重画文字：前台应用、菜单状态和时间变化会过期，不作为文字来源。
- 白字通过容器整体反相：实机出现背景偏色，改用 burn/screen 直接合成；像素检查约束两种极性背景保持一致。
- 修改系统壁纸或降低透明度偏好：存在全局副作用，不采用。

## Consequences

私有合成可能随系统版本失效。存在性检查只能避免已知缺失，不能保证未来 WindowServer 的合成语义；需要在目标系统上运行真实合成验证。当前实测 macOS 15.5，其他版本、多屏以及自动隐藏/全屏切换尚未完成平台验证。

背景估计在强纵向变化、彩色高亮菜单或辅助功能显示选项下可能有残差；右侧原始图标不经过归一化。动态壁纸只定期采样，不能承诺逐帧同步。增加屏幕捕获频率会提高开销，因此复用现有周期。

真实打包验证入口覆盖小数持久化、旧配置、无效输入、纹理模糊、黑白文字与背景像素、形状裁剪、拖动隐藏、零值恢复和迟到任务。隔离程序没有辅助功能授权时直接调用生产捕获/绘制路径，并明确不覆盖菜单发现、真实分段几何和点击交互。SwiftUI 设置页另以实际浅深色窗口快照检查。
